## Executive Summary

This document provides a comprehensive, end-to-end technical audit of all **datasets**, **feature contracts**, **data cleaning pipelines**, **split methodologies**, **machine learning architectures**, **reinforcement learning response policies**, and **cryptographic model artifacts** in the XRL-IDARS framework.

Every empirical metric and count reported in this document is derived directly from frozen result artifacts, raw data checksums, and reproducible multi-seed executions adhering to strict research rules:
1. **Zero Data Leakage:** Strict train/validation/test isolation with feature deduplication (Policy A) and training-only scaler fitting.
2. **Zero Sequence Boundary Crossing:** Temporal LSTM sequence construction strictly bounded within split partitions.
3. **Zero Synthetic Metric Fabrication:** All numbers reflect genuine model evaluations on real held-out test populations.
4. **Honest Metric Reporting:** Class-imbalance dominance is explicitly surfaced; F1-score and PR-AUC are treated as primary discriminators rather than raw accuracy.

## 2. Feature Contracts & Semantic Schema Mapping

A major flaw in intrusion detection literature is feeding raw, unharmonized feature sets into machine learning algorithms, leading to synthetic correlations and inability to evaluate models across different sensor feeds. XRL-IDARS enforces two strict feature contracts: **R10** (Primary) and **R4** (Fallback).

### 2.1 The R10 Feature Contract (Primary Flagship)

The **R10 Contract** consists of 10 flow-level behavioral features designed to provide rich spatial and temporal signals while remaining computational feasible for real-time line-rate extraction.

| # | Feature Identifier | Physical Formula / Derivation | Units | Operational Threat Directionality | Why It Matters |
|:--|:---|:---|:---:|:---|:---|
| 1 | `flow_duration_ms` | `duration_seconds * 1000` | ms | Microsecond flows indicate port scans; protracted flows indicate slowloris/exfiltration | Separates rapid scanning from interactive sessions |
| 2 | `flow_packets_per_s` | `total_packets / (duration_ms / 1000)` | pkts/s | Volumetric surges indicate flooding (SYN/UDP flood, DDoS) | Core volumetric rate signal |
| 3 | `flow_bytes_per_s` | `total_bytes / (duration_ms / 1000)` | bytes/s | Extreme throughput indicates high-bandwidth data exhaustion or exfiltration | Separates payload-heavy transfers from control packets |
| 4 | `packet_length_mean` | `total_bytes / total_packets` | bytes | Fixed-length packets characterize scripted toolkits; varied lengths characterize human traffic | Statistical size footprint |
| 5 | `packet_length_std` | Sample standard deviation of packet lengths | bytes | Low dispersion characterizes scripted flooding; high dispersion characterizes web/TLS handshakes | Key TreeSHAP discriminator |
| 6 | `syn_count` | Count of packets with TCP SYN flag set | pkts | High SYN counts indicate half-open SYN scanning or SYN flooding | TCP handshake initiation behavior |
| 7 | `ack_count` | Count of packets with TCP ACK flag set | pkts | Low ACK relative to SYN indicates unanswered connection requests | Half-open vs established state marker |
| 8 | `rst_count` | Count of packets with TCP RST flag set | pkts | Elevated RST count indicates port scanning (closed ports) or aborted sessions | Connection rejection metric |
| 9 | `fin_count` | Count of packets with TCP FIN flag set | pkts | Absence of FIN in high-packet flows indicates abrupt termination or spoofed sweeps | Graceful connection closure indicator |
| 10 | `syn_ack_ratio` | `syn_count / max(ack_count, 1)` | ratio | Ratio $\gg 1.0$ strongly indicates unreciprocated connection attempts | Direct mathematical signature of scanner/flooder |

### 2.2 The R4 Fallback Contract (Sensor Degradation Study)

UNSW-NB15 was generated using Argus and Bro-IDS, which did **not** export TCP flag counts, packet length standard deviation, or inter-arrival times in the published flow CSVs.
- **Scientific Decision (D-002):** Under no circumstances are missing features fabricated or imputed with zero. UNSW-NB15 is evaluated under the **R4 native contract** (`flow_duration_ms`, `flow_packets_per_s`, `flow_bytes_per_s`, `packet_length_mean`).
- This allows rigorous empirical evaluation of detector behavior under **sensor schema degradation**.

## 3. Splitting Methodology & Leakage Prevention Audit

### 3.1 Split Ratios & Seed Architecture
All datasets are partitioned into **60% Train**, **20% Validation**, and **20% Test** using deterministic pseudo-random seed `42` (with multi-seed robustness validated across seeds `42`, `123`, and `456`).
- **Train (60%):** Parameter learning only.
- **Validation (20%):** Hyperparameter tuning, calibration analysis, and fusion weight $\alpha$ selection.
- **Test (20%):** Held-out final evaluation, touched exactly once.

---

### 3.2 Duplicate Policy Audit: Policy A vs. Policy B

Network flow datasets contain massive volumes of identical flow records generated by repetitive background daemons. 

```
               ┌────────────────────────────────────────────────────────┐
               │                   Raw Ingested Flows                   │
               └──────────────────────────┬─────────────────────────────┘
                                          │
                               ┌──────────┴──────────┐
                               ▼                     ▼
                     [ Policy A: Deduplicate ]   [ Policy B: Retain All ]
                               │                     │
                     Deduplicate Features        Direct Random Split
                     BEFORE Splitting            Across Partitions
                               │                     │
                               ▼                     ▼
                     ┌──────────────────┐    ┌──────────────────┐
                     │ 0 Overlap Across │    │ 7,559 Cross-     │
                     │ Partitions       │    │ Partition Leaks  │
                     └──────────────────┘    └──────────────────┘
                            [PASS]                  [FAIL]
```

- **Policy B (Retain Duplicates):** Randomly splitting the data without prior deduplication resulted in **7,559 cross-partition duplicate overlaps** ($L-01$ leakage failure), severely inflating testing performance.
- **Policy A (Deduplicate Features - Enforced):** Deduplication is executed **prior to splitting**. Identical feature vectors are consolidated, guaranteeing **0 duplicate overlap** across train, validation, and test sets.

### 3.4 Preprocessing & Sequence Boundary Guarantees

1. **Preprocessing Isolation:** Missing value imputation (`SimpleImputer` using median) and feature normalization (`StandardScaler`) are fit **strictly on the training split**. Validation and test partitions are transformed using the frozen training parameters.
2. **LSTM Sequence Boundary Safety:** The Supervised LSTM constructs sliding windows of $T=5$ consecutive flows (`seq_len=5`). Sequence generation is executed **strictly after splitting** and bounded by capture files. No sequence is permitted to cross a train/validation/test boundary or a file boundary.
3. **Aligned Population Discrepancy:** Because an LSTM requires $T-1 = 4$ prior context steps, the first 4 flows of each disjoint file cannot form a valid sequence. This creates a tiny, mathematically proven discrepancy between tabular and sequence test populations:
   - **CIC-IDS2017:** 8 files $\times$ 4 context steps = **32 rows dropped** ($355,865 \to 355,833$ aligned test flows).
   - **CSE-CIC-IDS2018:** 10 files $\times$ 4 context steps = **40 rows dropped** ($1,662,459 \to 1,662,419$ aligned test flows).
   - **UNSW-NB15:** 2 files $\times$ 4 context steps = **8 rows dropped** ($24,504 \to 24,496$ aligned test flows).
   All direct model comparisons are evaluated exclusively on these **identically aligned populations**.

## 4. Model Architectures & Empirical Research Results

### 4.1 The Models Under Study

1. **Majority Class Classifier:** Establishes the empirical zero-rule performance floor under class imbalance.
2. **Logistic Regression & Decision Tree:** Standard linear and single-tree baselines.
3. **Random Forest Classifier (Primary Tabular Detector):** 100 estimators, balanced class weights, parallelized via scikit-learn. Fast sub-millisecond per-flow inference.
4. **Supervised LSTM (Temporal Sequence Classifier):** 2-layer PyTorch network, hidden size 32 (shipped checkpoints; the code default is 64), dropout 0.2, learning rate $10^{-3}$, Adam optimizer, binary cross-entropy loss. Evaluates temporal flow-to-flow dynamics over a sliding window ($T=5$). Memory-bounded on-the-fly mini-batching via `SequenceArray`.
5. **RF + LSTM Score Fusion (Ensemble):** Linear convex combination of predictions:
   $$S_{\text{fusion}} = \alpha \cdot S_{\text{RF}} + (1 - \alpha) \cdot S_{\text{LSTM}}$$
   where $\alpha \in [0, 1]$ is tuned on validation data.

### 4.3 Key Scientific Findings

1. **Why LSTM Outperforms RF on CSE-CIC-IDS2018:** On CSE-2018, the LSTM reduces the False Positive Rate from 2.59% (RF, 38,238 false alarms) to **0.26% (LSTM, 3,792 false alarms)** — a **10x reduction in false alarms** while increasing F1 from 0.8861 to 0.9603.
2. **Why $\alpha = 0.00$ on CSE-CIC-IDS2018:** On validation tuning, the LSTM's temporal boundary completely dominates the tabular RF. Incorporating RF predictions only degrades accuracy, so the optimal blend assigns weight 0 to RF.
3. **Severe Blindspots on Payload Attacks:** Coarse flow statistics fail to detect stealthy application attacks. Random Forest exhibits an **89.30% error rate on Infiltration** in CSE-2018 (recall 10.70%), an **84.11% error rate on Web Brute Force**, and a **97.22% error rate on XSS** in CIC-IDS2017.

## 5. Reinforcement Learning Autonomous Response (Phase 2)

### 5.1 Formulation
Intrusion detection without response leaves networks defenseless. XRL-IDARS introduces a **Dueling Deep Q-Network (Dueling DQN)** agent with Prioritized Experience Replay (PER) that observes network threat states and selects optimal mitigation actions.

- **State Representation (`response_state_v1` - 6 Dimensions):**
  1. $S_t$: Current Attack Risk Score ($P(\text{attack}) \in [0.0, 1.0]$)
  2. $\Delta S_t$: Score Trajectory / Trend ($\Delta S_t = S_t - \text{mean}(S_{t-k:t-1}) \in [-1.0, 1.0]$)
  3. $N_{\text{alert}}$: Recent Alert Density (fraction of past window flows $\ge 0.50$, $\in [0.0, 1.0]$)
  4. $a_{t-1}$: Normalized Previous Action ($a/3.0 \in [0.0, 1.0]$: ALLOW=0.0, ALERT=0.333, RATE_LIMIT=0.667, ISOLATE=1.0)
  5. $c_t$: Remaining Cooldown Fraction ($\in [0.0, 1.0]$)
  6. $v_t$: Normalized Coarse Volumetric Scale ($\log_{10}(1 + \text{bytes\_per\_s}) / \text{scale\_max} \in [0.0, 1.0]$)
- **Action Space:**
  - **3-Action Policy:** `ALLOW` (0), `ALERT` (1), `RATE_LIMIT` (2)
  - **4-Action Policy:** `ALLOW` (0), `ALERT` (1), `RATE_LIMIT` (2), `ISOLATE` (3)
- **Reward / Cost Function ($C_{\text{flow}}$):**
  Penalizes uncontained attacks, unnecessary throttles, false isolations of critical assets, and action chattering.
