## 1. Executive Summary

Modern cybersecurity operations centers (SOCs) face an overwhelming volume of alerts generated by passive intrusion detection systems (IDS). While machine learning (ML) and deep learning (DL) models achieve high benchmark accuracy in identifying anomalous traffic flows, passive detection creates an alert-fatigue crisis where analysts cannot triage incidents in real time. Conversely, fully automated response mechanisms risk catastrophic self-inflicted Denial of Service (DoS) if false positives trigger aggressive host isolation or traffic disruption.

The **Explainable Reinforcement Learning Based Intrusion Detection and Autonomous Response System (XRL-IDARS v1)** addresses this fundamental operational dilemma by constructing a unified, scientifically audited pipeline that bridges:
1. **Passive Intrusion Detection:** Flow-level Random Forest (RF), Supervised Long Short-Term Memory (LSTM), and Score Fusion models trained across three multi-file benchmark datasets comprising 20 physical files and over 19 million network flows.
2. **Autonomous Response Decision-Making:** A Deep Q-Network (DQN) agent operating over a continuous 6-dimensional causal state representation, optimized against a dual-objective reward function that explicitly balances intrusion damage cost against operational disruption cost.
3. **Dual-Layer Explainability:** Combining global TreeSHAP feature attributions on detector classifications with localized, human-auditable decision cards explaining every autonomous mitigation action.
4. **Deterministic Non-Bypassable Safety Layer:** An algorithmic constraint governor enforcing strict blast-radius circuit breakers (maximum 5% isolated endpoints), mandatory action cooldowns (preventing high-frequency oscillation), critical infrastructure exemptions (preventing gateway/DNS isolation), and action-space bounds.
5. **Atomic Rollback & Response Transaction Harness:** An isolated-network actuation architecture ensuring that every automated mitigation is preceded by a cryptographic state snapshot, verified post-action, monitored by watchdog timers, and automatically rolled back upon failure or timeout.

### Summary of Authoritative Project Outcomes
- **Phase 1 (Intrusion Detection):** Developed a strictly frozen 10-feature cross-dataset contract (R10) and eliminated cross-split duplicate leakage (Policy A deduplication). Proved that temporal sequence modeling (LSTM) and tuned score fusion consistently enhance flow-level discrimination across multiple datasets, but established that unadapted cross-dataset transfer suffers severe degradation (52% to 95% F1 reduction) and identified severe stealth-attack blindspots.
- **Phase 2 (Autonomous Response):** Evaluated DQN response intelligence against four deterministic baselines across 355,865 held-out test flows. The DQN agent achieved **statistically significant cost reductions** of **11.29%** in the Balanced regime and **14.10%** in the Aggressive regime ($p < 0.001$). However, under the pre-registered scientific criteria, the practical effect-size threshold ($\ge 15.0\%$ cost reduction) was **NOT MET**.
- **Phase 3 (Live Network Validation & Controlled Response):** Transitioned the pipeline from offline replay to real Linux networking. Validated streaming bidirectional flow reconstruction (Decision D-006), live feature calculation parity ($\text{atol} \le 10^{-4}$), dry-run burst processing, multi-tier packet ingestion stress, 29 adversarial attack scenarios, 8 cryptographic tamper vectors, and multi-target concurrent transactions. Cryptographic host baseline comparisons verified **exactly zero host network mutations** (`pre == post` SHA-256).

> [!CAUTION]
> **Authoritative Operational Scope Boundary:**  
> XRL-IDARS v1 is **scientifically validated** in offline benchmarks and **experimentally validated** within isolated Linux network namespaces (`10.200.1.0/24`). It **DOES NOT** claim production readiness, universal generalization, or deployment readiness on uncontrolled enterprise or campus networks.

## 2. Research Questions & Empirical Answers

All ten research questions defined in [`docs/00_PROJECT/RESEARCH_QUESTIONS.md`](file:///home/rishikesh/Desktop/fyp-xrlids/docs/00_PROJECT/RESEARCH_QUESTIONS.md) are answered below based solely on committed experimental artifacts.

### RQ1: Can flow-level ML distinguish benign and malicious traffic?
- **Exact Question:** *Can flow-level ML distinguish benign and malicious traffic?*
- **Empirical Answer:** **YES, within domain under strict feature contracts.** On held-out, deduplicated test sets with zero split leakage, Random Forest models achieved high discriminative performance:
  - **CIC-IDS2017:** Accuracy = 0.9815, F1 = 0.9512, ROC-AUC = 0.9968 (on 355,833 test flows).
  - **CSE-CIC-IDS2018:** Accuracy = 0.9723, F1 = 0.8861, ROC-AUC = 0.9902 (on 1,662,419 test flows).
  - **UNSW-NB15 (R4 Contract):** Accuracy = 0.8590, F1 = 0.8548, ROC-AUC = 0.9487 (on 24,496 test flows).
- **Primary Artifacts:** `results/experiments/EXP-P1-CIC2017-R10-001/test_metrics.json`, `results/experiments/EXP-P1-CSE2018-R10-MULTI-001/test_metrics.json`, `results/experiments/EXP-P1-UNSWNB15-R10-MULTI-001/test_metrics.json`.
- **Limitations:** High aggregate metrics mask severe attack-family blind spots. At the frozen $\tau = 0.50$ baseline, stealthy attacks exhibit unacceptable recall (e.g., Infiltration recall = 10.70%, Web attacks recall = 2.78% on CIC-IDS2017).

### RQ2: Does temporal information improve detection?
- **Exact Question:** *Does temporal information improve detection?*
- **Empirical Answer:** **YES, on structured sequence populations.** Evaluating Supervised LSTM models over aligned flow sequences ($T=5$) demonstrated improved discrimination compared to flow-independent Random Forest models:
  - **CIC-IDS2017:** LSTM achieved F1 = 0.9633 (+0.0121 over RF F1 = 0.9512, $p < 0.0001$).
  - **CSE-CIC-IDS2018:** LSTM achieved F1 = 0.9603 (+0.0742 over RF F1 = 0.8861, $p < 0.0001$).
  - **UNSW-NB15:** LSTM achieved F1 = 0.8637 (+0.0089 over RF F1 = 0.8548, $p < 0.0001$).
- **Primary Artifacts:** `results/experiments/EXP-P1-*-R10-MULTI-001/test_metrics.json`.
- **Limitations:** Sequence processing incurs substantial latency overhead (~10–20x higher inference duration per flow compared to RF) and requires sequential flow alignment.

### RQ3: Does RF + LSTM fusion outperform the individual models?
- **Exact Question:** *Does RF + LSTM fusion outperform the individual models?*
- **Empirical Answer:** **YES on these held-out test populations.** Validation-tuned convex score fusion ($S_{\text{fusion}} = \alpha \cdot S_{\text{RF}} + (1 - \alpha) \cdot S_{\text{LSTM}}$; the blended score is not a calibrated probability) achieved the highest overall detection quality across all three domains:
  - **CIC-IDS2017 ($\alpha=0.50$):** F1 = 0.9745 (+0.0233 over RF, +0.0112 over LSTM, $p < 0.0001$).
  - **CSE-CIC-IDS2018 ($\alpha=0.00$):** F1 = 0.9603 (LSTM dominated; pure temporal model selected).
  - **UNSW-NB15 ($\alpha=0.60$):** F1 = 0.8970 (+0.0422 over RF, +0.0333 over LSTM, $p < 0.0001$).
- **Primary Artifacts:** `results/experiments/EXP-P1-*-R10-MULTI-001/test_metrics.json`.
- **Limitations:** Optimal mixing parameter $\alpha$ varies substantially across network environments (ranging from 0.0 to 0.6), requiring target-domain weight tuning.

### RQ5: How does the model behave under dataset / domain shift?
- **Exact Question:** *How does the model behave under dataset / domain shift?*
- **Empirical Answer:** **CATASTROPHIC DEGRADATION.** Evaluating models across all six transfer directions without target domain adaptation revealed severe covariate shift:
  - **CIC-IDS2017 $\to$ CSE-CIC-IDS2018:** F1 dropped from 0.9512 to 0.3286 (-65.5% relative drop).
  - **CSE-CIC-IDS2018 $\to$ CIC-IDS2017:** F1 dropped from 0.8861 to 0.0301 (-96.6% relative drop).
  - **Auxiliary Transfers (UNSW $\leftrightarrow$ CIC/CSE):** F1 dropped by 52% to 95%, with precision collapsing to near-zero.
- **Primary Artifacts:** `results/experiments/EXP-P1-TRANSFER-*/`, `reports/generated/transfer_report.md`.
- **Limitations:** Confirms that supervised intrusion detection models cannot be deployed zero-shot across disparate enterprise networks without explicit domain adaptation.

### RQ6: Which features drive predictions?
- **Exact Question:** *Which features drive predictions?*
- **Empirical Answer:** **IDENTIFIED VIA TREESHAP.** TreeSHAP attributions across all models revealed that flow discrimination is primarily driven by:
  1. `packet_length_std` and `packet_length_mean` (payload size variance distinguishes uniform attack traffic from variable benign traffic).
  2. `flow_duration_ms` and `flow_packets_per_s` (timing anomalies distinguish volumetric floods and port scans).
  3. `syn_count` and `syn_ack_ratio` (transport handshake state anomalies).
- **Primary Artifacts:** `results/experiments/EXP-P1-*-R10-MULTI-001/shap_summary.json`.
- **Limitations:** SHAP attributions reflect associative correlations learned by tree partitions; they do not imply underlying network causality.

## 4. Phase 2 Findings — Autonomous Response Intelligence & Safety Layer

Phase 2 constructed and evaluated the autonomous response framework, benchmarking RL against heuristic baselines under pre-registered audit criteria.

### 4.1 Causal State Representation & Action Space
- Formulated a 6-dimensional continuous state representation:
  $$s_t = \langle S_{\text{det}}, C_{\text{family}}, P_{\text{conf}}, R_{\text{flow}}, H_{\text{crit}}, A_{\text{current}} \rangle$$
- Defined graded, discrete mitigation actions: `ALLOW (0)`, `ALERT (1)`, `RATE_LIMIT (2)`, `ISOLATE (3)`.

### 4.2 Deterministic Safety Gate Architecture
To guarantee that RL exploration or policy errors cannot induce network outages, all proposed actions pass through a non-bypassable governor:
1. **Critical Infrastructure Exemption:** Gateway and core server IPs are exempt from `ISOLATE` (clamped to `ALERT`).
2. **Blast Radius Circuit Breaker:** Restricts concurrent endpoint isolation to a maximum of 5% of the active host population.
3. **Mandatory Action Cooldown:** Enforces a 30-step cooldown window following disruptive actions, preventing rapid oscillation back to `ALLOW`.
4. **Action Space Mode Enforcement:** In 3-action operating mode, any proposed `ISOLATE` is deterministically clamped to `RATE_LIMIT`.

### 4.3 Held-Out Final Evaluation ($D_{\text{pol\_test}}$, 355,865 Flows)
Evaluated across three operational cost regimes on completely untouched test traffic:

| Operational Cost Regime | Optimal Baseline | Baseline Total Cost | DQN Total Cost | Cost Reduction | Paired Bootstrap $p$-value | Practical Criterion ($\ge 15\%$) |
|:---|:---|:---:|:---:|:---:|:---:|:---:|
| **Balanced** ($C_{\text{FP}}=1, C_{\text{FN}}=10$) | Static-RateLimit | 204,185 | **181,133** | **+11.29%** | $p < 0.001$ | **NOT MET** |
| **Aggressive** ($C_{\text{FP}}=1, C_{\text{FN}}=20$) | Static-RateLimit | 362,810 | **311,645** | **+14.10%** | $p < 0.001$ | **NOT MET** |

## 8. Known Limitations & Negative Findings

In accordance with scientific integrity standards, all limitations and negative results are explicitly cataloged:

1. **Practical Cost Criterion Not Met (RQ7):** While the DQN policy achieved statistically significant cost reductions ($p < 0.001$), the pre-registered practical significance threshold ($\ge 15.0\%$ cost reduction) was not achieved (11.29% and 14.10%).
2. **Catastrophic Cross-Dataset Degradation (RQ5):** Detectors trained on one network environment collapse when evaluated on another without target adaptation, demonstrating lack of universal zero-shot transferability.
3. **Stealth Attack Blind Spots (RQ1):** High aggregate F1 scores mask near-total detection failure on stealthy attack classes (Infiltration recall 10.70%, Web attacks recall 2.78% at $\tau=0.50$).
4. **Vulnerability to Score Jitter (Phase 2D):** Perturbations or uncalibrated noise in detector confidence scores cause policy instability, degrading response efficiency toward static baselines.
5. **Detector Inference Latency Bottleneck (Phase 3E):** Deep learning and Random Forest inference on CPU cores (median 47.6 ms/flow) represents the primary throughput bottleneck, limiting high-speed packet ingestion without dedicated hardware accelerators.
6. **Single-Node Concurrency Architecture:** The current implementation uses single-node multi-threading with target-scoped locks; it lacks distributed consensus (e.g., Raft) for multi-node enterprise deployments.
7. **No Production Hardware / Kernel-Bypass Actuation:** Actuation is implemented via Linux network namespaces and virtual interfaces; production deployment requires kernel-bypass mechanisms (e.g., eBPF / XDP).
8. **No Live Accuracy Claims Without Ground Truth (§64):** Real-time predictions on unmanaged traffic are reported strictly as flow counts and latency metrics, never as accuracy metrics, due to the absence of independent packet-level ground truth.
9. **Row-Level Split Optimism (Quantified):** The primary splits are row-level. Exact feature-duplicate vectors are removed across splits, but host-disjoint grouping is not applied; near-duplicate flows from the same traffic burst can still share a split. The strict CSE temporal holdout (§3.6) removes same-day overlap and shows the optimism is severe: RF F1 falls from 0.8861 to 0.0113, bot recall from 99.17% to 0.09%, and infiltration recall from 10.70% to 0.94% on the surviving unique future attacks. In-domain metrics must therefore be read as upper bounds, not future-day performance. Grouped-by-host validation was not executed because no stable host key is available.
