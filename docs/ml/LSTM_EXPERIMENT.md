## 1. Problem Background: Forensic Audit of Historical Checkpoints

Prior checkpoints in the repository (`models/lstm/lstm_cse2018.pt`, `lstm_cicids2017.pt`) exhibited severe methodological defects:
1. **Row-Permutation Leakage**: Training data was generated by taking tabular CSV rows and slicing them into windows of 5 without grouping by host IP or ordering by timestamp. The resulting sequences contained flows from unrelated machines interleaved randomly.
2. **Missing Identifiers**: 16 out of 17 attack families in the benchmark suites lacked IP addresses, making true multi-flow sequence assembly physically impossible.
3. **Temporal Inversion**: Historical ablation experiments demonstrated that reversing the order of sequence flows produced identical evaluation metrics, proving that the historical LSTM was not learning temporal dynamics.

---

## 2. Rigorous Chronological Sequence Methodology

Experiment `EXP-P2-LSTM-VALID-001` resolved these issues by establishing a scientifically sound sequence generation pipeline:
- **Eligible Dataset**: `Thuesday-20-02-2018_TrafficForML_CICFlowMeter.csv` (CSE-CIC-IDS2018), the only benchmark file with full 5-tuple IPs and monotonic timestamps.
- **Active Attack Window**: Focused on the 75-minute volumetric flood ($t = 1519121000 \to 1519125500$).
- **Grouping Invariant**: Flows were grouped strictly by source IP (`host_id`) and ordered monotonically by start time (`ts`).
- **Buffer Flush Invariant**: Gaps $> 300.0\,\text{s}$ between flows flushed the host buffer.
- **Purge Gaps**: 120-second buffers separated the Train, Validation, and Test splits.
- **Unseen Attacker Isolation**: AWS attacker instances `18.218.11.51`, `18.219.32.43`, and `18.218.115.60` were held out exclusively in the test set.

### Split Population Counts:
- **Train Sequences**: 47,559
- **Validation Sequences**: 8,732
- **Held-Out Test Sequences**: 8,726 (including 1,179 unseen attacker sequences)

## 4. Why the LSTM Remains Experimental

While the LSTM achieved a valid F1-score of $0.9996$, four fatal operational flaws prevent its deployment as an operational detector:
1. **Marginal Improvement**: The $+0.19\%$ F1 gain represents only **16 additional flows** correctly classified out of 8,726.
2. **Cold-Start Blindness**: The LSTM is completely blind to single-flow and micro-burst attacks ($K < 5$), returning `None` for flows 1 through 4.
3. **State-Exhaustion Vulnerability**: Maintaining sliding flow tables per host IP exposes the NIDS to memory exhaustion under IP-spoofed flood attacks.
4. **Dataset Inapplicability**: Cannot be trained or validated on 16 out of 17 attack families due to lack of network identifiers in standard benchmark datasets.

**Conclusion**: Outcome B (RF-Only Operational Detector) is certified. The LSTM is retained strictly as an academic research baseline.
