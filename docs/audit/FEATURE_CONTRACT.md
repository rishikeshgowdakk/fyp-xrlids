## 1. Executive Summary & Historical Context

In early project iterations, an architectural mismatch existed between:
1. **CIC-IDS2017 Benchmark Data:** Generated by CICFlowMeter as bidirectional 5-tuple network flows with flow-level statistics (durations, inter-arrival times, flag counts, packet length distributions).
2. **Early Live Capture Script:** Aggregated host-level traffic statistics across arbitrary 1-second sliding time windows, creating an incompatible feature space where models trained on flow metrics were fed windowed host aggregates.

### Authoritative Resolution: Decision D-006
Under Decision D-006, the live traffic processing pipeline was completely redesigned and unified with the offline feature contract:
- Replaced the host-level time-window aggregator with a **pure-Python streaming bidirectional 5-tuple flow builder** (`src/xrlids/demo/flow.py`, `src/xrlids/live/flow_builder.py`).
- Adopted the standard **D-006 Hybrid Completion Policy**:
  - Immediate flow termination on TCP `FIN` or `RST` flags (connection teardown).
  - 120.0-second idle timeout fallback for inactive or connectionless (UDP/ICMP) flows.
- Established strict numerical parity ($\text{atol} \le 10^{-4}$) between live flow feature calculation and the canonical mathematical definitions in `src/xrlids/features/definitions.py`.

## 3. Detailed Boundary Verification

### A. Flow Definition & Key Canonicalization
- **5-Tuple:** `(src_ip, dst_ip, src_port, dst_port, protocol)`.
- **Bidirectional Symmetry:** In `FlowKey.from_packet()`, endpoints are lexicographically ordered:
  $$\text{ep}_1 = (\text{ip}_1, \text{port}_1), \quad \text{ep}_2 = (\text{ip}_2, \text{port}_2)$$
  If $\text{ep}_1 \le \text{ep}_2$, direction is forward; otherwise reverse. Both directions hash to the identical `FlowKey`.
- **Connectionless Protocols (UDP/ICMP):** Handled transparently by the same 5-tuple key.

### B. Timestamp & Duration Semantics
- **Replay Mode:** Timestamps are read directly from the PCAP packet header (`ts_sec + ts_usec * 1e-6`). Pacing accurately reproduces recorded inter-arrival times.
- **Live Interface Mode:** Timestamps use system wall-clock / arrival time (`time.time()`).
- **Zero-Duration Flows:** Sub-microsecond flows (e.g. single packet or immediate RST) use $\max(\Delta t, 10^{-6}\text{s})$ as the effective denominator for rate calculation, preventing divide-by-zero or infinity.

### C. Packet Length Statistics
- Packet lengths represent the full IPv4 packet length (`max(total_len, len(ip_bytes))`), matching the L3 packet length convention of CICFlowMeter.
- Standard deviation uses $N$-denominator (`ddof=0`) matching the offline formula. Single-packet flows default to `std = 0.0`.

### D. Edge-Case Robustness
- **Retransmissions:** Packet lengths and flags are accumulated normally, exactly as CICFlowMeter does on raw wire captures.
- **Incomplete Handshakes:** Flows with SYNs but no ACKs accumulate `syn_count >= 1` and `ack_count = 0`, producing an elevated `syn_ack_ratio >= 1.0` (indicative of port scanning / SYN flood).
- **Missing / Infinite Values:** Live extraction computes values directly from integers and positive timestamps, guaranteeing zero `NaN` or `Inf` in the live pipeline.

### E. Preprocessing & Scaling Parity
- Random Forest and LSTM were trained on data scaled via `Preprocessor` (`StandardScaler`).
- The fitted scaler is serialized at `results/experiments/EXP-P1-CIC2017-R10-001/preprocessor.joblib`.
- During live inference (`FlagshipXRLIDS.process_flow` and `dashboard.server`), the live R10 vector is transformed using this exact frozen training scaler before evaluating the models:
  ```python
  df_scaled = self.preprocessor.transform(df_contract)
  p_rf = float(self.rf_detector.predict_proba(df_scaled)[0])
  ```
- **Feature Order Verification:** The Random Forest detector enforces `expected == list(X.columns)` and raises `RandomForestError` on any discrepancy.

## 4. Multi-Topology Parity Evidence

Automated integration tests (`tests/integration/test_feature_parity.py` and `tests/integration/test_phase3_parity_harness.py`) execute across 5 controlled network topologies:
1. Standard Interactive TCP (Handshake + HTTP GET/POST + FIN Teardown)
2. SYN Flood / Port Scan (Repeated SYNs, no ACKs, trailing RST)
3. Connectionless UDP Traffic (DNS Query and Response)
4. Asymmetric Bulk Data Transfer (20 large packets, periodic ACKs)
5. Micro-Duration Flow (Sub-millisecond single-burst exchange)

**Verification Outcome:**
All 10 features achieve numerical parity within the pre-registered tolerances ($\text{atol} \le 10^{-4}$ for lengths/ratios/durations, $\text{atol} \le 10^{-3}$ for rates, $0.0$ for flag counts) across all 5 topologies.
